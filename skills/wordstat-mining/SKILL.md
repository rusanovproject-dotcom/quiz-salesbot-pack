# Добыча спроса

Ты не гадаешь, какими словами люди ищут нишу владельца — ты **спрашиваешь у Яндекса**. Wordstat отдаёт реальные фразы и их частоту. Это не абстрактный SEO-ресёрч: цифры идут прямо в квиз.

**Не начинай без `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md` с заполненным разделом «Дело».** Нет его — возвращайся к навыку `funnel-interview`. Без ниши и продукта спрашивать Wordstat не о чем.

## Зачем это квизу

Реклама ведёт человека прямо в квиз, минуя лендинг: клик по объявлению — уже намерение, лишний экран между ними только теряет людей. Но это работает, только если **первый экран квиза зеркалит формулировку объявления и ключевика** — иначе мостик рвётся, человек видит незнакомые слова и уходит. Wordstat — это и есть источник тех слов, которыми реально ищут, а не тех, которые придумал владелец на лендинге.

Два места, куда идут цифры:

1. **Первый экран (`facade.kicker`, `facade.title`, `facade.sub`)** — берёшь самую частотную живую формулировку из топа, а не общую фразу вроде «пройди тест». «Подбор кухни на заказ» бьёт по тому же нерву, что реклама, и человек узнаёт себя с первой секунды.
2. **Варианты ответов** (вопросы 2–5 из `build-quiz` — сфера, боль, что берёт первым) — частотность подсказывает, какие формулировки боли и запроса ставить первыми и заметнее. Фраза с частотой 3000/мес не то же самое, что фраза с частотой 40/мес: первая — то, что реально волнует массово, вторая — редкий частный случай, ей не место на первом плане.

Разбор общего принципа «реклама → квиз без лендинга» — `playbook/01-принцип-воронки.md`. Здесь — только источник слов для него.

## Ключ: официальный API (Yandex Cloud)

Инструмент — `skills/wordstat-mining/scripts/wordstat.sh`, официальный Search API v2. Не парсер, не серый доступ.

**Как получить ключ** (шаги, консоль Yandex Cloud может по-другому называть пункты меню — ориентируйся по смыслу, не по точному тексту):

1. Зайди в консоль облака (`console.cloud.yandex.ru` или актуальный домен AI Studio/Cloud — Яндекс периодически переименовывает витрину, ищи в поиске «Yandex Cloud консоль»).
2. Создай или выбери каталог (folder). Скопируй `folder_id` — он в URL страницы каталога.
3. Найди раздел «Сервисные аккаунты» → создай сервисный аккаунт.
4. У сервисного аккаунта выпусти **API-ключ** (не IAM-токен — тот живёт час и для скрипта не годится, API-ключ не истекает).
5. Убедись, что сервис Search API (Wordstat) подключён в этом каталоге — иногда нужно отдельно активировать сервис в каталоге перед первым запросом.
6. Сохрани ключ и id каталога:

```bash
mkdir -p ~/.secrets
cat > ~/.secrets/wordstat.json <<'JSON'
{ "api_key": "<API-ключ сервисного аккаунта>", "folder_id": "<id каталога>" }
JSON
chmod 600 ~/.secrets/wordstat.json
```

Нет ключа или платного аккаунта в облаке — не блокируй сборку, переходи к фолбэку ниже.

## Команды

```bash
skills/wordstat-mining/scripts/wordstat.sh top "фраза" [N] [--region ID[,ID...]]     # частотность + похожие фразы
skills/wordstat-mining/scripts/wordstat.sh regions "фраза" [--top N]                 # где спрос по регионам
```

| Аргумент | Что | Дефолт |
|---|---|---|
| `top "фраза"` | Частотность фразы + похожие запросы | — |
| `N` (позиционный) | Сколько похожих фраз вернуть | 50 |
| `--region ID[,ID…]` | geoId региона, можно списком | **нет — считает по всей России** |
| `regions "фраза"` | Разбивка спроса по регионам | — |
| `--top N` | Сколько регионов показать | 15 |

### Главная ловушка — регион обязателен

Без `--region` API считает частотность по всей России, и цифра завышена в разы. Живой пример: «кухни на заказ» — 76094 по РФ, но 9763 в Москве и всего 1090 в Новосибирске. Если ниша владельца локальная (мастер, студия, региональный бизнес) — федеральная цифра врёт про его реальный рынок в разы.

**Порядок:**
1. Ниша не знает своего региона — спроси у владельца или подними `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md`.
2. Сомнение в регионе → сначала `regions "фраза"`, посмотри, где вообще есть спрос, оттуда бери geoId.
3. Только потом `top "фраза" --region <geoId>`.

Частые geoId — в шапке `skills/wordstat-mining/scripts/wordstat.sh` (Россия 225, Москва 213, СПб 2, Новосибирск 65, Екатеринбург 54 и ещё полтора десятка городов). Города нет в списке — не гадай, узнай через `regions`.

## Что делать с результатом

Из `top`:
- `results[]` — первая строка это частотность самой фразы за месяц в этом регионе, дальше — похожие фразы, у каждой своя частота. Отдельного поля `totalCount` в ответе нет — не ищи его.
- Похожие фразы из `results[]` — материал для вариантов ответов и заголовков.

Забирай в квиз только **живые, узнаваемые фразы** — не самые частотные абстрактно, а те, что звучат как речь клиента (сверяй с разделом «Его слова» в `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md` — если фраза из Wordstat совпадает по смыслу с тем, что реально говорил клиент, это сильный сигнал брать её).

## Фолбэк без ключа — ручной чек-лист wordstat.yandex.ru

Ключа нет или не завёлся — не изображай, что подключил API. Скажи прямо и веди владельца руками:

1. Открыть `wordstat.yandex.ru`, войти под своим Яндекс-аккаунтом.
2. В поле региона (сверху) выставить нужный город/регион — **без этого шага цифры будут федеральные и завышенные**, та же ловушка, что и в API.
3. Ввести маску запроса (ту же, что использовал бы в объявлении).
4. Записать из **левой колонки** («Что искали пользователи, искавшие „фраза“») — топ-20 фраз с частотностью каждой.
5. Заглянуть в **правую колонку** («Запросы, похожие на „фраза“») — это ассоциации, расширение вбок: подсказки для новых вариантов ответа или для минус-слов.
6. Занести в `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md` список: фраза → частотность → куда легла (см. ниже).

Разница с API — только в способе получения цифр, требования к региону и итоговый формат одинаковые.

## Выход в FUNNEL-BRIEF.md

Обновляешь **существующий** файл, секции не переименовываешь.

**В «Его слова (дословно)»** — дописываешь фразы из Wordstat, которые совпали с реальным языком клиента, отдельным подпунктом «из Wordstat» (не смешивай с цитатами из переписок — источник должен быть виден).

**В «Решения по сборке»** — новый подпункт списком, куда легла каждая ключевая фраза:

```markdown
### Ключевики → куда легли
| Фраза | Частотность (регион) | Куда легла |
|---|---|---|
| подбор кухни на заказ | 1090 (Новосибирск, 65) | facade.title |
| кухня не влезает в бюджет | 340 (Новосибирск, 65) | вопрос 4 (боль), вариант ответа |
| замер кухни бесплатно | 210 (Новосибирск, 65) | facade.support |
```

Регион в каждой строке обязателен — цифра без региона в этой таблице не цифра, а мусор.

## Частые ошибки

| Что | Почему |
|---|---|
| Взял частотность без `--region` | Цифра завышена в разы, решения по важности фраз будут неверными |
| Слепо взял самую частотную фразу | Частая ≠ узнаваемая. Сверяй с «Его слова» — фраза должна звучать как речь клиента, а не как абстрактный запрос |
| Ключа нет — сказал, что данных не будет | Есть ручной фолбэк через wordstat.yandex.ru, он обязателен, а не опционален |
| Записал цифру в `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md` без региона | Следующий скилл (оффер) не сможет доверять числу — оно может быть федеральным враньём |
| Смешал цитаты клиента и фразы из Wordstat в одном месте | Источник должен быть виден — это разные по силе сигналы |
| Изменил порядок или названия секций `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md` | Ломает контракт со всеми остальными скиллами цепочки |
