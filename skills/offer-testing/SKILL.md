# Тест офферов после запуска

Воронка уже живая. Вопрос не «как собрать», а **что именно чинить первым**. Не гадать по ощущению — читать три точки воронки раздельно и трогать одну переменную за раз.

**Не начинай без действующей воронки.** Квиз опубликован (доступен по ссылке, `api/quiz.js` смотрит на `QUIZ_INTAKE_URL`) и идёт трафик — то есть хотя бы одна карточка уже легла в `LEADS_DIR`. Ни одной карточки нет — тестировать нечего: либо трафика ещё не запускали, либо приёмник не поднят (проверь `GET /health` у `intake.py`).

## Три точки воронки — читай раздельно

Просадка в разных местах — это разные гипотезы и разные правки. Смешал точки — чинишь не то.

- **Старт.** Кликнул рекламу → открыл первый экран квиза. Отвечают заголовок и визуал первого экрана, мостик с формулировкой объявления.
- **Завершение.** Открыл → дошёл до экрана результата. Отвечают длина квиза, порядок вопросов, конкретный вопрос, на котором рвётся.
- **Контакт.** Дошёл до результата → нажал кнопку в бота (или оставил телефон в запасном поле «напомнить позже»). Отвечают текст результата, оффер («что получу»), включён ли `askPhone` для тех, кто не нажал кнопку.

Ориентиры (не гарантия — это диапазон из чужой практики, а не твои цифры): старт 20-40% от кликнувших рекламу, завершение 65-80% от открывших, контакт около 40% от дошедших до результата. Числа ниже — сигнал копать, не приговор: у тебя может быть иначе и это нормально.

## Где просело → что тестировать

| Просело | Симптом | Вероятная причина | Что менять первым |
|---|---|---|---|
| Старт | открыли квиз заметно реже, чем кликают по рекламе | заголовок/визуал не цепляет, оффер не совпадает с объявлением | `facade.kicker/title/sub`, визуал первого экрана, формулировку под конкретное объявление |
| Завершение | дошли до результата заметно реже, чем начали | квиз ощущается долгим, конкретный вопрос роняет людей | число и порядок вопросов, формулировку проблемного вопроса, пояснение у чувствительного (деньги/размер) |
| Контакт | дошли до результата, но не оставили данные | результат не убеждает нажать основную кнопку в бота, а запасного пути для тех, кто не нажал, — нет | `result.ctaText/ctaButton/fallbackNote`, переключатель `askPhone` (добавляет на экране результата второй шаг «напомнить позже» с полем телефона — запасной путь для тех, кто не кликнул основную кнопку), сам оффер результата |

Если просело сразу в двух точках — чини сначала старт: пока люди не доходят до квиза, чинить середину бессмысленно.

## Как считать без готовой аналитики

`LEADS_DIR` не знает про старт — карточка появляется только на завершении (первый `POST /quiz-submit` уходит сразу после результата, ещё без телефона). Старт меряй счётчиком на странице квиза (Метрика, пиксель рекламного кабинета) — без него ты вообще не видишь эту точку.

Счётчик Метрики — та же порода исключения, что строка шрифтов в навыке `quiz-design`: код квиза в остальном не трогаем, но здесь одна строка перед `</head>` в `projects/<project_slug>/funnels/<funnel_slug>/quiz/index.html` — осознанное отступление от «движок не трогаем», не лазейка. Альтернатива, если у владельца уже есть аналитика хостинга (пиксель рекламного кабинета, счётчик на уровне сервера) — используй её вместо правки движка, она ничего не ломает.

Завершение и контакт — из самих карточек. Контакт отличаешь по непустому `phone`, а не по факту существования файла:

```bash
LEADS_DIR=~/quiz-leads   # путь, который реально стоит в config.env у intake.py

ls "$LEADS_DIR"/*.json 2>/dev/null | wc -l   # завершили квиз (дошли до результата)

python3 - "$LEADS_DIR" <<'EOF'
import json, sys, pathlib
base = pathlib.Path(sys.argv[1])
total = with_phone = 0
for f in base.glob("*.json"):
    c = json.loads(f.read_text())
    total += 1
    if c.get("phone"):
        with_phone += 1
if total:
    print(f"завершили: {total} · оставили контакт: {with_phone} · контакт%: {with_phone/total*100:.0f}")
else:
    print("карточек ещё нет")
EOF
```

Один `quiz_id` — один файл, повторный приход дополняет, а не плодит дубль (см. `ingest()` в `intake.py`) — так что счёт файлов честный, без переучёта.

## Порядок теста

Один экран за раз, в этой последовательности:

1. Первый экран/заголовок (`facade`) — самая большая точка обвала, чинится первой
2. Первый вопрос — второй по весу для завершения
3. Заголовок и текст экрана результата (`result`) — для контакта

**Одна переменная за раз.** Поменял заголовок и картинку сразу — не узнаешь, что сработало.

## Правило объёма

Не делай вывод раньше **1000 кликов** по рекламе на этот вариант **или** потраченного бюджета в **три стоимости клиента** — что наступит раньше. Держи тест **1-2 недели**: конверсия скачет по дням недели, пяти дней недостаточно, чтобы отличить сигнал от шума.

## Цикл гипотез

1. **Гипотеза** — «думаю, просело N из-за такой-то причины» (одна фраза, без «наверное всё сразу»)
2. **Одно изменение** — правишь ровно то, что назвал в гипотезе
3. **Замер** — держишь до порога объёма/времени выше, считаешь по формуле из раздела «как считать»
4. **Запись** — вывод уходит в `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md`, секцию «Решения по сборке», отдельным блоком в конец (append, не переписывать старое)
5. Следующая гипотеза — только после записи предыдущей

Формат записи в `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md`:

```markdown
### Журнал тестов офферов

**2026-08-20** — старт 15% (низко). Гипотеза: заголовок не мостится с объявлением
про «Х». Изменил `facade.title` на цитату из объявления. Через 9 дней / 1200 кликов
старт вырос до 27%. Оставляю, следующая гипотеза — вопрос о размере роняет завершение.
```

Это твои цифры, не примеры из этого файла — не копируй значения выше буквально.

## Частые ошибки

| Что | Почему плохо |
|-----|--------------|
| Меняешь заголовок, визуал и вопросы одним заходом | не узнаешь, что именно сработало |
| Делаешь вывод по 50 кликам | шум ещё не улёгся, решение будет случайным |
| Чинишь вопросы, когда просел старт | середина неважна, пока люди не доходят до квиза |
| Путаешь «карточка есть» с «оставил контакт» | карточка появляется уже на завершении, контакт — отдельно по `phone` |
| Нет счётчика на странице квиза | точку «старт» вообще не видно — тестируешь вслепую половину воронки |
| Держишь тест 2-3 дня | конверсия колеблется по дням, вывод будет случайным |
| Не записал вывод в `projects/<project_slug>/funnels/<funnel_slug>/FUNNEL-BRIEF.md` | через месяц повторишь тот же тест и ту же ошибку |
